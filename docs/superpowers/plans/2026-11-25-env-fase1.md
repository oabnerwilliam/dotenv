# .env Fase 1 — Roteiro de implementação

> **Para agentes:** este roteiro divide a fase em histórias. Cada história é um PR. Cada arquivo de história traz seu plano de implementação em TDD; o `planejador` o confere contra o código antes de começar. Convenções e versões em [`2026-11-26-env-fase1-convencoes.md`](2026-11-26-env-fase1-convencoes.md). Fluxo e sessões autônomas em `CLAUDE.md`.

**Objetivo:** controle manual de ambientes de homologação, com login Google, convites e publicação no ar.

**Arquitetura:** React fala com o Supabase Auth para o login e com a API NestJS para todo o resto. Só a API acessa o Postgres (Prisma). Tipos e regras puras ficam em `packages/shared`.

**Stack:** pnpm workspaces, React + Vite + Tailwind CSS v4, NestJS, Prisma, Supabase, Zod, Jest, Vitest, Playwright.

**Spec:** [`../specs/2026-11-25-env-fase1-design.md`](../specs/2026-11-25-env-fase1-design.md)

## Restrições globais
- Node 22, pnpm 10.
- `apps/web`, `apps/api`, `packages/shared`.
- Interface em pt-BR; a palavra "equipe" numa constante única.
- Alvos ≥ 44px, contraste ≥ 4.5:1, foco visível, uso completo por teclado.
- Tokens só de `docs/design/docs/tokens.css`; nenhum hex solto.
- RLS em todas as tabelas, sem políticas públicas; toda consulta filtrada pela equipe.
- Repositório público: sem segredos, `.env*` ou nomes e dados reais.
- Portões: `pnpm lint`, `pnpm typecheck`, `pnpm test`, `pnpm test:e2e`, `pnpm build`.

## Foco de revisão
1. Duas pessoas reservam o mesmo ambiente ao mesmo tempo: só uma consegue; a outra vê erro claro e a tela atualizada (09).
2. Usuário de uma equipe usa o id de um projeto ou ambiente de outra: recebe "não encontrado" (05, repetido em 06–11).
3. Regex de ticket inválida ou patológica nas Configurações: a inválida é recusada ao salvar e nenhuma derruba o board (06, 07).
4. E-mail do convite com maiúsculas ou espaços: o convite funciona (04).
5. Reserva vence enquanto o modal de liberar ou o drawer está aberto: a ação não falha com erro genérico nem duplica o evento (09).
